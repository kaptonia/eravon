# link corpus

The generated corpus of `eravon.link/1` (docs/eravon-link-v1.md), built by
`gen.py --seed N` from the law, `eravon.terms/1`, and HARNESS-LINK.md, with
the shared helpers in `../gencommon.py`. Seed 1 is committed;
`../compare.py link` runs a candidate named by `ERL_CANDIDATE` and the
criterion `../link-py/erl.py` over `manifest.json`.

- `listings/`: listings and near-listings for `check`, `bind`,
  `bind-receipt`; the `gl1_*` listings carry the inputs of the `galeed/1`
  corpus's `check` set (`../../galeed-conformance/corpus/canon/`, 3,656 at
  that corpus's committed seed), so that `galeed/1` §3 is witnessed on a
  surface where no test of this law decides before `canonical(b)`, its
  first test over the whole input among them (law §11.1).
- `links/`: links for `link-check`, `encode`, `resolve-link`.
- `docs/`: the documents `resolve-link` is handed as fetched bytes.
- `receipts/`, `packs/`, `settles/`: receipts, case packs, settlement
  offers.
- `texts/`: link and receipt texts for `decode` and `receipt-decode`.
- `terms/`: terms documents for `bind`.
- `records/`: record sets of one chain for `place`, `pay-check` and
  `history`, each answer predicted by the generator's own replay of the
  book and its own reading of §6; every list of two or more elements is
  written out of position order, by seed, and every record set with such a
  list is written again in ascending position (`<slug>_asc`), so that a
  reader that reverses its lists, or merges a kind of list as given, meets
  a case at every seed whatever the shuffle drew.

The manifest's form, the role of `predicted`, and the seed's reach are as
the terms corpus README states them.

Every command that reads a path once with an unreadable one, every command once with an argument short and once with an argument beyond the list (`gen_misuse` and each section); `erl` alone; an unknown command, with and without a path.
