# dossier corpus

The generated corpus of `eravon.dossier/1` (docs/eravon-dossier-v1.md),
built by `gen.py --seed N` from the law, the two document laws, and
HARNESS-DOSSIER.md, with the shared helpers in `../gencommon.py`. Seed 1 is
committed; `../compare.py dossier` runs a candidate named by
`ERD_CANDIDATE` and the criterion `../dossier-py/erd.py` over
`manifest.json`.

- `dossiers/`: one directory per case, `dossier.json` and the files it
  names; a case's `path` is the directory. Five cases carry symbolic
  links (one dangling, one to a regular file, one through a second link,
  one as `dossier.json` itself, one a loop of two); no entry's resolution
  follows more than two links, but for the loop, which no host resolves;
  one case carries a directory named `dossier.json`, a file inside it so
  that the committed tree carries the directory. The `gl1_*` cases carry,
  each as its entry file, one input of the `galeed/1` corpus's `check` set
  that passes `galeed/1` §3.5 (`../../galeed-conformance/corpus/canon/` as generated at seed 1 and committed,
  854 at that corpus's committed seed, the same bytes under every seed
  here), the listing and receipt of `ok_ruled` beside it.

The manifest's form, the role of `predicted`, and the seed's reach are as
the terms corpus README states them.
