# ERAVON 用户手册

本手册介绍 ERAVON 0.1.0 版的桌面客户端(`eravon-app`,供卖家与买家使用),并简要介绍命令行(`eravon`)。成交全在桌面客户端里做:卖家发布商品,买家打开付款链接付款,两边都不经网页。

## 1. ERAVON 是什么

ERAVON 在以太坊上运行托管订单。每一笔订单是一个合约实例,在订单结束前托管买家的货款。每笔订单的条款都写明一位判官,或一个以抽签方式指定判官的行会;买卖双方有分歧时,由这位判官裁决。

各方角色:

- **卖家**:在桌面客户端中设置商品。发布时客户端为商品生成条款文档,对卖家选定的每位判官或行会签一份要约,把这一版发上链上公告板,并给出付款链接(`eravon://open?e=<载荷>`,格式为 `eravon.link/1`)与它的二维码。卖家把链接发给买家,之后跟进每笔订单:交付、应对争议、和解或退款。每单的判官费与押金在开案时从卖家的金库拉取。
- **买家**:把付款链接交给桌面客户端(点击链接、粘贴或扫码)。客户端从公告板读出这一版、逐项核验,买家选定判官、签署订单,把货款付到这笔订单自己的地址(预算地址),然后开案。交付之后,买家确认收货,或在确认期内申请退款,由判官在条款的全部档位里裁决。
- *判官或行会*:写在条款中,由买家在付款时选定。发生争议时,判官在裁决期内裁决。桌面客户端没有判官席。

### 1.1 本版本的现状

- **链**:以太坊主网与 Sepolia,两条链一视同仁,不上 L2。家在哪条链,建家时选定(首启向导的 **网络** 一步、新建与导入身份的单上;不选即表上头一行,以太坊主网),此后在设置 › 网络里切换;关于页 **网络** 一行写所在的网;每个网各有一张节点表,切到哪个网就读哪个网、扫哪个网、只显示哪个网的单。新建商品、付款开案与一切新交易走所在网的现行合约;往代合约上的案默认不显示,在设置 › 网络打开 **往代显示** 后照它那一代的合约操作(见 5.5 节)。节点表答别的链即具名拒。
- *判官登记簿*:判官文档与行会名录都要经所在网的判官登记簿读取。以太坊主网与 Sepolia 上的登记簿是同一个地址(`0x5da2894fc5260832330305f50f948401b3c904d8`)。
- *平台*:桌面客户端在它支持的每个系统上由同一份源码构建(macOS、Linux 与 Windows)。选择文件使用系统自带的选档面板(系统没有面板时,把文件拖入拖放区),Linux 的 Wayland 桌面上窗口同样收拖入的文件;在 Linux 上,收文件也收目录的地方先问选文件还是目录。提醒以系统通知送达。`eravon://` 链接在 macOS 上经 app 包登记;在 Linux 与 Windows 上,客户端每次启动为当前用户登记这个协议。客户端已经开着时,再点一条链接,链接交给开着的那一个,不另开窗口。

## 2. 构建与启动

0.1.0 版以安装包发布在[发布页](https://github.com/kaptonia/eravon/releases/tag/v0.1.0),可用 [`SHA256SUMS.txt`](https://github.com/kaptonia/eravon/releases/download/v0.1.0/SHA256SUMS.txt) 核对;各包怎样安装见 README 的「安装」一节:

- macOS 11 起,Apple 芯片:[`ERAVON-0.1.0-macos-arm64.dmg`](https://github.com/kaptonia/eravon/releases/download/v0.1.0/ERAVON-0.1.0-macos-arm64.dmg) 或 [`ERAVON-0.1.0-macos-arm64.pkg`](https://github.com/kaptonia/eravon/releases/download/v0.1.0/ERAVON-0.1.0-macos-arm64.pkg)。窗口从 `ERAVON.app` 打开;命令行是 `ERAVON.app/Contents/MacOS/eravon`,用 pkg 安装时另有 `/usr/local/bin/eravon`。数据在 `~/Library/Application Support/ERAVON/`。
- Linux x86_64,glibc 2.31 起:[`eravon-app_0.1.0_amd64.deb`](https://github.com/kaptonia/eravon/releases/download/v0.1.0/eravon-app_0.1.0_amd64.deb)(窗口从应用菜单打开,`eravon-app` 与 `eravon` 装在 `/usr/bin`)或 [`ERAVON-0.1.0-x86_64.AppImage`](https://github.com/kaptonia/eravon/releases/download/v0.1.0/ERAVON-0.1.0-x86_64.AppImage)(带 `window` 运行)。数据在 `~/.local/share/ERAVON/`。
- Windows 10 与 11,x86_64:[`ERAVON-0.1.0-windows-x86_64.zip`](https://github.com/kaptonia/eravon/releases/download/v0.1.0/ERAVON-0.1.0-windows-x86_64.zip);解压后双击 `eravon-app.exe`,命令行是旁边的 `eravon.exe`。数据在 `%LOCALAPPDATA%\ERAVON\`。
- 源码:[`eravon-0.1.0-src.tar.gz`](https://github.com/kaptonia/eravon/releases/download/v0.1.0/eravon-0.1.0-src.tar.gz),照下文构建。

### 2.1 构建

在仓库根目录执行:

```
cargo build --release
```

Rust 工具链版本固定在 `rust-toolchain.toml` 中,rustup 会自动选用。本手册涉及的两个程序位于 `target/release`:

- `eravon-app`:桌面客户端。
- `eravon`:命令行。

### 2.2 启动桌面客户端

```
target/release/eravon-app window [--data <数据目录>] [--lang en] [--url <链接>]
```

- `--data`:存放金库、钥、设置、订单与操作日志的目录;不给时用系统应用数据里的 `ERAVON` 目录,与装好的客户端相同。每次都使用同一个目录。
- `--lang`:启动时的界面语言,`zh`(默认)或 `en`。
- `--url`:启动时交给客户端的一条 `eravon://open?e=` 链接(付款链接或和解要约)。同一数据目录的客户端已经开着时,这条链接交给开着的那一个,本次启动随即结束。

在终端里不带参数运行 `eravon-app`,会报用法错误并以退出码 2 退出;在终端里,窗口只经 `window` 打开。

*app 包(macOS)*:要从访达启动 ERAVON,并让 `eravon://` 链接能打开它,先生成 app 包:

```
target/release/eravon-app bundle --at <目录> --data <数据目录>
```

这会在 `<目录>` 中写出 `ERAVON.app`。该 app 包未签名,供本机使用。它记住数据目录,启动时无需参数。点击 `eravon://open?e=` 链接会启动该 app 包并把链接交给它。

## 3. 首次启动与安全

### 3.1 首次启动向导

数据目录中还没有金库时,客户端打开首次启动向导。

1. **设置口令**:8 位字母或数字(区分大小写),输入两次。8 位全同的口令会被拒绝;全为数字时,顺序连号(如 `12345678`)或看起来像日期的也会被拒绝,并说明违反了哪一条规则。
2. **创建身份**:可先填 **备注**(可不填),再选一种方式:
   - **生成助记词**:客户端生成 12 个助记词。点 **确认无人看屏幕后点按显示**,按顺序抄在纸上,点 **我已抄在纸上**,再输入客户端要求的三个词,点 **确认并创建**。
   - **导入已有密钥**:输入 **助记词**(12 个词可整段粘贴到第 1 格)。只收本客户端生成的钥,裸私钥与密钥文件不收。只凭助记词只能恢复链上读得到的数据。
   - **从备份恢复**:拖入或选择整机备份,输入备份密码。这会替换本机的身份与数据。
3. **网络**:选这一席的家在哪条链(**以太坊主网** 或 **Sepolia 测试网**,默认选中表上头一行),点 **下一步** 即定;之后可在 设置 › 网络 里切换。
4. **我是**:选择 **卖家** 或 **买家**,两个选项下各有一行说明,之后可随时切换。
5. *卖家:收款地址*:货款打入的地址。可点 **以后再说** 跳过,之后在 **付款方式** 页填写。
6. **导出备份**:写出这台机器的整机备份(卡上写明 **内容**:几把钥、几条记录)。可点 **以后再做**,之后在 设置 › 本机数据 中导出。

还没有身份时收到一条付款链接(点击、`--url` 或粘贴),链接先存着:向导顶上写明有一条链接在等,**我是** 默认选 **买家**,导入订单这一步可以以后再做;向导结束即回到这条链接。客户端锁着时收到的链接,解锁后打开。

最后一步点 **完成** 结束向导并进入主界面;没做完的步骤可在 设置 › 关于 里继续。

### 3.2 席位与钥

客户端有 **卖家** 与 **买家** 两个席位,用左侧边栏顶部的分段控件切换。每个席位有自己的钥。第一次进入另一个席位时,会有一段简短向导为它添加一把钥(先是身份步,再是网络与该席位的那一步)。

左上角的身份条显示当前钥。点击它可在本席位内切换钥,或进入 **新建身份**、**导入密钥** 与 **身份密钥**。

**设置** › **身份密钥** 顶上是当前身份卡(名字、席位与种类、**复制地址**;卡上列 **密钥地址**、**gas 余额** 与 **备份状态**),其下依次是 **口令**(**修改口令**、**自动锁定**、**闲置时长**)、**导出**(**导出密钥文件**、**显示助记词**)、**身份**(**主身份**、**设为主身份**、**切换身份**、**新建身份**、**导入密钥**、**改名**)、**详细信息**,页底是 **删除身份**(删的是当前这一把;主身份不能删除,删前要输入口令)。**切换身份** 打开一张弹层,本席的每把钥一张卡,点开就地展开看地址,点 **切换** 即换;**新建身份** 生成一把新的 12 词钥(**生成 12 个词**,然后 **确认无人看屏幕后点按显示**、**我已抄在纸上**,输入要求的三个词后点 **确认并创建**);**导入密钥** 凭 **助记词** 添加一把钥并给它一个 **备注**,不在词表里的词当即标红;**改名** 只改这把钥在本机的名字,地址与密钥都不变。新建或导入的钥不受口令保护,只能凭这 12 个词找回。

**换钥**(设置 › 身份密钥):打开 **延续身份**,先列出这一趟要做的事(**要发的交易**、**在途案归新钥**、**补登记的已付单**、**补登记的在售商品**、**重签后押金改由新钥出**),每一张已付未开的单可改成 **到期退款,不补登记**,每一件在售商品可改成 **撤下,不补登记**;两席共用一套词时,清单与笔数连另一席的单与商品一并列出,另一席读不成即照名说出;确认后在这一席的家所在的那条网上由旧钥声明、新钥接任,新钥的十二个词只显示这一次。换钥之后身份与它的数据都留在原处:身份菜单行数不变,席位的在任钥换成新钥,两席一起换;新的十二个词即这一身份的助记词(主身份的恢复也改用它,旧词不再打得开)。导入的单钥身份换钥得一把新单钥,不出示词;它的 **备份状态** 回到未备份,卡上写明重新导出钥档或重做整机备份。旧钥签出而没人提交的回执、动作与和解在接任之后作废;旧钥的历史会公开连到新钥,收不回。中途停下的链显示 **续做**。卖家钥上还有代币时先说出来:可到钱包转出,或点 **仍要换钥**,币留在前任钥上,换成后在钱包 **前任钥上的钱** 点 **转到当前钥** 转回;押金签在旧钥上的已付未开的单到期退款。中途停下的换钥照常续做。换钥做到一半时做的整机备份,恢复到别的机器上再接着做完,会说新的十二个词不在这台机器上:这一身份的助记词与恢复封仍是旧词,要在原来那台机器上做完再备份一次。不延续即另添一把新钥,作为新身份并切过去,与旧钥无关联。

### 3.3 口令、锁定与恢复

- 边栏底部的 **锁定**(或 Cmd+L;macOS 以外的系统为 Ctrl+L)立即锁定客户端。锁定会让进行中的付款在下一笔交易发出前停下。
- **自动锁定**(设置 › 身份密钥 › 口令)默认开启,闲置 15 分钟后锁定。**闲置时长** 可选 1、5、15、30 或 60 分钟。
- 启动时和锁定后显示 **输入口令**。输满第八个字符即开始核对,格子随即清空,核对期间不再收键;格子下方一行写 **核对中**,拒了即在同一处写原因,再按键即收起。连续输错 5 次后显示 **已锁定**,此时只能恢复。
- **忘记口令** 进入 **恢复**,能走哪几条路随主身份的种类(解锁前从金库头读出):
  - 主身份是助记词:**助记词** 为主,输入主钥的 12 个助记词,然后两次输入新口令;其下折着 **从密钥文件还原**,用它任一席位导出的密钥文件与文件口令也能恢复。
  - 主身份是导入的钥:**从密钥文件还原**,用它导出的那份密钥文件与文件口令。
  - 两种都另有 **从备份恢复**:拖入整机备份并输入备份密码,这会替换本机的身份与数据。没有主身份时只剩这一条。
- **修改口令**(设置 › 身份密钥 › 口令)要求输入当前口令,再两次输入新口令。
- 密钥库读不成时,锁屏只有一条出路:**挪开本机数据,重新开始**。确认弹层写明挪走哪个目录(改名放在旁边,不删一字节)、哪个数据目录原地不动,以及 **回来的路**;点 **挪开并重新开始** 后首次启动向导再走一遍,可用整机备份或助记词恢复。另一个窗口或命令行正写着本机数据时,弹层上具名拒(`MACHINE_HELD`),什么也不挪。

### 3.4 备份与密钥文件

在设置 › 身份密钥 › 导出中:

- **显示助记词**:输入口令后显示主钥的 12 个助记词。
- **导出密钥文件**:把加密的密钥文件写入 **保存位置**(默认是「文稿」目录,弹层左下 **选择目录** 可改)。先输入口令,再两次输入至少 8 位的文件口令。密钥文件只救得回主身份:忘记口令时 **从密钥文件还原** 只认主身份那一份,别的身份导出的密钥文件无处可收,要保住它们请用整机备份。
在设置 › **本机数据** 中(另显示数据目录):

- **整机备份**:**导出备份** 把身份与本机数据备份到 **保存位置**(默认是上次备份所在的目录,否则「文稿」目录;弹层左下 **选择目录** 可改),用至少 8 位的备份密码保护(有强度提示);导出时弹层留着,底部一行报到哪一步(**整理**、**加密**、**写入文件**、**回读核对**),写好才关,其间返回与 Esc 不收。**查看备份** 选一份备份、输入备份密码,只列出它的建立时间与内容,不替换任何东西。**从备份恢复** 用备份替换本机的身份与数据,备份中没有的内容会丢失。**上次备份** 显示上次备份的时间以及此后的改动条数。只凭助记词只能恢复链上数据,请保持备份及时。

设置 › **命令行与 AI 控制**(终端与 AI 代理自动控制)一节两组:

- **终端** › **启用 eravon 命令** 把随应用装的 `eravon` 命令行接进终端,终端里直接敲 `eravon` 即可(macOS 上系统可能要管理员确认)。关上只移除这个开关自己建的;那一处已被别的安装占着时,开关会说明并不去动它。
- **终端** › **接入 AI 应用** › **复制配置**:复制让 AI 应用起 `eravon mcp` 的配置(见 `CLI-SCHEMA.md` 第 13 节),贴进 AI 应用的设置即可。**经凭据操作**关着时,复制出的配置不带程序钥;开着时,**复制配置**先过口令、为这一份添一把程序钥(附注**接入 AI 应用**与时刻),再连钥带配置复制,钥在 `env` 里,形如 `"env":{"ERAVON_CLI_PASS":"evp_…"}`(整段见 `CLI-SCHEMA.md` 第 13 节);钥没添成就不复制。不带钥的配置,在本机经凭据写时它的写答 `E_CREDENTIAL_PASS_MISSING`。命令行在 app 外够不到的安装方式(就地打开的磁盘映像、AppImage)下此键灰着。
- **自动控制等级** › **经桌面 App 操作**(桌面解锁时可用):开着时,命令行带 `--desktop <数据目录>` 的动词由本窗做完(见第 8 节);关上即答 `E_DESKTOP`(`NOT_OPEN`,退出码 4)。这个开关存在本机,重启照旧。
- **自动控制等级** › **经凭据操作**:输入口令并定有效期(天、小时、分钟,或 **不过期**)后,命令行与 AI 应用不用口令写本机数据,到期或关掉为止(见 `CLI-SCHEMA.md` 第 12 节);只在桌面没开着这一家时写得成,桌面开着时写答 `E_CREDENTIAL_DESKTOP_HOLDS`:先退出桌面,或关掉 **经凭据操作** 改经桌面写。开着时 **经桌面 App 操作** 灰着,带 `--desktop` 的动词答 `E_DESKTOP`(`ALONE`):去掉 `--desktop` 即可。
- **程序钥**(**经凭据操作** 开着时):命令行替哪个程序做事,那个程序就带它自己的一把钥。**添加程序钥** 要一句附言与口令,钥只显示这一次(当场复制;之后不再显示,也不落盘),交给那个程序放进环境变量 `ERAVON_CLI_PASS`。每行显示附言与添加时间;**删除** 当即收回这一把,别的不动。关掉 **经凭据操作**,或换了新主钥,凭据连同其中每把程序钥一起删去。旧版留下的凭据(一把钥给所有程序)不再认:开锁时删去、关掉 **经凭据操作** 并说一次,命令行遇到即答 `E_CREDENTIAL_SHAPE` 并删去;重新打开、再添程序钥即可。

## 4. 主界面

- *边栏*:卖家席为 **首页**、**订单**、**待上链**、**商品**、**判官与行会**、**导出**、**钱包**、**付款方式**、**通知**;买家席为 **首页**、**订单**、**待上链**、**付款链接**、**钱包**、**通知**、**导出**。底部是 **设置** 与 **锁定**。**通知** 上的数字是待处理事项的条数。
- *状态行*:边栏最底部一次只说一件事,按先后取第一样成立的:你起的长动作正在进行(写出它的名字);**正在同步…**;**未配置节点**、**节点有误** 或 **节点在别链**(节点答的不是所在网那条链,提示里写明把节点换回所在网的节点);**同步失败**;上次同步的时刻(同一天只写时与分,隔了天另写月与日,按 设置 › 语言和时间 所选的时区写;过了十分钟这一行转为琥珀色);**尚未同步**。几个节点是否一致与块号见 设置 › 网络。旁边的键即刷新,首页与通知也会重新读取。
- *工具栏*:子页面上有返回箭头,返回之后出现前进箭头。页面操作位于右侧;详情页(订单、商品、编辑页)的标题与操作键在页内大标题行。
- *提示*:操作结果以顶部的短提示显示,一次一条;出错时分两行,先写出了什么事,再写下一步;复制成功只写 **已复制**。**详情** 显示原始错误,**收起** 关闭提示。
- *快捷键*:Cmd+1 至 Cmd+6 打开边栏前六项,Cmd+[ 与 Cmd+] 返回与前进,Cmd+, 打开设置,Cmd+L 锁定,Esc 关闭弹层。这里的 Cmd(⌘)在 macOS 上是 Command 键,在其他系统上是 Ctrl 键。
- *按钮变灰*:操作无法执行时,页面顶部的横幅说明原因:**已锁定,解锁后可编辑**、**请先在 设置 › 身份密钥 中添加钥**、**请先在 设置 › 网络 中添加节点**、**节点配置有误,请在 设置 › 网络 中修改** 或 **尚未同步,请先刷新**。原因在节点上时,横幅右端有 **网络** 键,直达 设置 › 网络。
- **拖入订单文件**:在买家席,把订单文件拖到窗口任意位置,会打开 **付款链接** › **导入** 并选中该文件(付款页上打开着一段正文页、正等着拖入正文核对时除外,见 6.1 节)。
- *链接*:交给客户端的 `eravon://open?e=` 链接(经 `--url`、点击链接,或在没有输入框获得焦点时按 Cmd+V 粘贴)会落到对应页面:付款链接落到 **付款链接** › **付款**;链接所指的若是一份和解要约,落到买家这一单的争议页签并读出要约。若有其他操作正在进行,链接在其完成后打开。
- *二维码*:付款链接、收款地址、待付款与回执等处的二维码都由同一处画出;内容装不进二维码时,写明 **这段内容做不成二维码,请改用复制**。

### 4.1 证据披露包(ZIKARON)

ZIKARON 是另一个应用,用可信的时间链保存证据。连接后,它的披露包会列在两个席位的证据弹层中,可以作为证据提交。设置 › **ZIKARON**:

- **连接 ZIKARON**:打开或关闭连接(默认开启)。关闭时不做任何探测,证据弹层不列披露包。
- **机器目录**:显示 ZIKARON 所在位置(**自动发现**,或手动指定);点 **更换** 打开 **更改机器目录**,弹层左下 **选择目录** 选好后点 **保存**。
- **详细信息**:说明它是如何找到的(**手动指定**、**指针文件** 或 **默认目录**)、有多少个披露包,或为什么没有连接。

## 5. 卖家

### 5.1 首先要填的设置

- **设置** › **网络**:首启时节点表已静默填好各网的出厂节点(每网两家以上、不同运营方);**RPC 节点** 一卡逐行列出这些节点,行尾一键移除一家;卡下一格添加一家(`https://…`,或 `链号=地址` 加到别的网),已在表上的不重收。**节点最大问数上限** 一行只收 1 至 1000 的整数(默认 256),按 **确认上限** 即与节点表存在一处,命令行与 AI 应用读同一个数,界外的数不存。**REST API 模式** 开关默认关,打开后出现 **REST API** 一卡:填 **Base URL**(以 `https://` 开头、不带查询串,如 Etherscan V2 的 `https://api.etherscan.io/v2/api`)与 **API Key** 添加一行;钥匙只存在这台机器的封存设置里,随整机备份走,行上只显示末四位;启动桌面客户端前以环境变量 `ERAVON_REST_KEYS` 指一份钥档(每行「服务 钥」),设置里没存钥的行即用钥档的钥,钥档给了钥的服务添加时 **API Key** 可留空;命令行以 `--rest-keys <钥档>` 给同一份钥档(`eravon mcp` 照样转给它起的命令);钥档不写进设置与备份,钥不回显;同一服务只算一处、只收一行。REST 服务答不了的问(不带地址的日志、费用历史、指定块号的余额)不问它,读数取自其余节点。关掉开关,各行留着、不问。卡片上写出 **节点** 个数(读链时问的节点,开着的 REST 行在内)、**合约版本** 与 **链上读取**(**多端一致**、**单节点** 或 **尚未同步**);其下的详细信息列出节点原文、**合约** 地址与 **块号**。**自动刷新** 在 设置 › 通知:新装时每 60 秒一次;行内的格以秒填写周期,留空或填 0 即 **仅手动**,按回车或 **保存** 即存,存后格旁写 **已保存**。周期只管定时的那一种刷新;解锁、换钥、换节点、你自己的动作落地与刷新键照旧会读链;读数过了十分钟照样标为已旧。读链与发交易都只经这张表,节点须在所在网那条链上。卡片上的合约版本与详细信息里的合约地址,即所在网现行的那一份合约,版内不能更换。**代理** 三选一:**跟随系统代理**(读系统的代理设置,含自动配置脚本)、**关闭代理** 或 **自定义代理**。自定义时分格填 **类型**(HTTP、HTTPS、SOCKS5、SOCKS4)、**主机**、**端口**、**用户名** 与密码(SOCKS4 只有 **用户 ID**,不带密码);整段代理地址可粘贴进主机格,离开该格即拆进各格。保存后,地址回显不带密码,密码格清空、只写 **已设密码**;同一代理、同一用户名再保存而不填密码,留用原密码;盘上不留明文密码。
- **付款方式** 页 › **加密钱包付款** › **收款地址**:显示当前钥的收款地址(短写,可复制)或 **未设置**。未设置时点 **设置地址**,已设置时点 **更换**,输入两次地址,再点 **保存**。更换后,在售商品会重新签名。
- **设置** › **身份密钥**:身份卡上的 **gas 余额** 写签名钥上的 ETH(用于支付交易手续费)与读取时刻,取自上次同步的读数;还没读过时写 **未读取**。
- **设置** › **关于** › **重新运行向导**:从第一个没做完的步打开本席向导(做完的步勾着、可回看);做完只写那一步留下的东西,例如收款地址。

### 5.2 付款方式与开案设置

**付款方式** 页只有 **加密钱包付款**(始终开启,**默认**):买家把钱付到这笔订单自己的地址。这张卡里有 **收款地址**(见 5.1)。

**设置** › **开案设置**(只在卖家席)三项,改了只用于之后发布的版本,已发出的链接照旧:

- **见款自动开案**:货款到账后,客户端在解锁时补开,按 **同步** 时也开。关着时不代开,这一单写 **已到款,待开案**,在订单页点 **立即开案**。
- **开案期限**:天、小时、分钟三格;付款后这段时间里没有开案,买家可全额取回。
- **允许买家自付 gas 开案**:买家付款后可以自己开案。押金大到不小于货款而这一项开着时,钱包页会提醒:任一买家开案都会从金库拉这笔押金。

每项后面有 **保存**。

### 5.3 判官与行会

**判官与行会** 页有 **候选判官** 与 **候选行会** 两个分段。

- **添加判官** 需要判官的 **地址** 与 **备注**。**添加行会** 需要行会的 **指针**(`galeed:guild:1:0x…`)与 **备注**。
- 每一行显示备注名、它的地址(短写,同名的两项由此分开)、一行概要(判官为规则版本与受理状态;行会为成员数与方式)以及状态:**可选**、**无报价**、**接单期限太短**(池报价的接单期限短于这条链要的最短期限,不能选)、**需重新签名**、**格式有误**、**无法获取**、**未通过验证** 或 **已停业**。判官登记簿的情况见 1.1 节。
- 点一行查看详情。判官有 **概况**、**约法**、**报价**、**记录** 四个页签;行会有 **概况**、**约法**、**报价**、**成员** 四个页签。概况照原文列出资料写的 **名称**、**主页** 与说明,以及读取所在的完整 **地址**,并标明这个地址 **带码·合约** 还是 **无码·钥**;这个判官换过地址时,**走过的地址** 逐跳列出每一个,读的是最后一个;它的记录上尚未生效或已被替换的继任声明,含现行钥挂着未承接的那一条,列为 **继任尝试**(照原样列出,由你自己判断)。资料表外的成员照原文列出,本应用不读它们。行会概况另列名录里的 **行会自述**。行会的 **成员** 页签逐个列出名录写的地址与它继任到的地址(成员资料有名称时名称在前、地址不藏),同样标明带码与否;每位成员资料里的主页、说明、继任尝试与名录元素里 `addr` 之外的成员,在这一位的折叠项里照原文列出。报价列出 **判官费**、**诉讼费**、**接单期**、**裁决期**、**辞任条款**(点进去逐种情形写明判官不作为时钱往哪走)、**单笔上限** 与 **接单**,并附示例金额。
- **修改备注名** 后点 **保存备注名** 修改备注名。**移除此项** 后点 **移除** 把候选从列表中去掉,它不再出现在商品的判官列表中。
- 候选有更新时显示 **需重新签名**,使用它的链接会重新签名。

### 5.4 商品与付款链接

**商品** 页列出商品的名称、状态、判官与价格,并有搜索框。状态有 **草稿**、**已下架**、**待签** 与 **在售**,列表与商品页同用这几个词。

**新商品** 打开编辑页,共五个页签:**基本信息**、**交付物**、**退款**、**候选判官**、**确认**。页内大标题行右端有 **取消**、**保存**、**发布** 三个键;**发布** 在每个页签上都在,只在 **确认** 页签上、条款齐全且费用已列出时才亮,灰着时悬停写明还差哪几项。

- **基本信息**:**名称**、**说明**、**商品页面**(**可不填**)、**图片**(**可不填**,**添加图片** 只记图片名与 SHA-256)、**价格**、**结算币**(从本机 设置 › **币种** 表里登记的本链币种中选)。说明用 Markdown 编辑器写:工具行有 **标题**、**粗体**、**斜体**、**列表**、**编号列表**、**引用**、**代码** 与 **导入正文**(用一个文本文件整篇替换),字数在下方,**详情** 里是 **正文摘要**。商品页面与图片写在说明正文的末尾,随正文一起冻结(写法见本节末)。
- **交付物**:**交付期限** 与 **确认期限**,各分天、小时(0 到 23)、分钟(0 到 59)三格;空格即 0,每个期限须大于零。**交付说明**,用 Markdown 编辑器写。
- **退款**:**退款档位**,每档有档名和退给买家的比例,档旁注 **诉讼费买家担** 或 **诉讼费卖家担**。第一档(0%)与最后一档(100%)固定;**添加档位** 在两者之间插入新档,总数最多 16 档,比例须递增。争议时的诉讼费在第一档由买家承担,其余各档由卖家承担。
- **候选判官**:**候选判官** 与 **候选行会** 两张卡,打开要提供的那几位;每行注明它的辞任条款。只有状态为可选的候选才能打开。
- **确认**:**基本信息**、**交付物**、**退款**、**候选判官** 逐节汇总,各节有 **修改** 跳回那一页签;其下是每位候选按这一价格收的 **费用** 与 **辞任条款**。保存过而还缺项时,编辑页顶上写 **草稿 · 还需填写:** 与所缺的项。

**保存** 只存草稿,不签名。**发布** 生成条款文档,用你的签名钥对每位选定的候选签署要约,并以一笔交易把这一版发上链上公告板(手续费由签名钥付);上板之后才有付款链接。发布落定即转到这件商品的商品页,在售标记、付款链接与上板状态都在那一页。如果此时客户端处于锁定状态,商品显示 **待签**,解锁后再签名;签好而还没上板时,商品页写明 **这一版还没上公告板:上板后才出付款链接**,并有 **上公告板** 键。带着未保存的改动离开编辑页时,会询问 **保存商品?**(**保存**、**不保存**、**继续编辑**)。修改即发布新版本、换新链接;当前版本及其链接在新版本发布前保持有效。 **只发布,不上公告板** 签好这一版、出好清单与付款链接,不发上板那一笔;上板留在商品页的 **上公告板**,何时上由你定。

商品页顶上是商品名、价格与状态,右端是 **编辑**;其下依次是 **基本信息**(**价格**、**交付期限**、**确认期限**、**退款档位**、**候选判官**)、**商品描述**、**辞任条款**、**付款链接** 一节,页底是这一版的收尾键:草稿为 **删除草稿**,在售为 **在链上下架**,本机下架的一版为 **上架**,已在链上下架为 **发布新版本**。

- **商品描述** 一节列出 **商品说明** 与 **交付说明** 各一行(草稿写 **已填写** 或 **未填写**,发布后写 **全文上板** 或 **只上摘要**),点一行打开那一段的正文页;说明里写了商品页面时另有 **商品页面** 一行,整行在浏览器打开,行尾可复制。商品说明的正文页列出图片名与 SHA-256,把图片拖进来(或点 **选择文件**)即现算核对。
- 链接状态:**链接可下单**、**已下架**,或 **暂无链接** 及原因;上过板的一版在状态下写已上公告板与那一笔交易。
- **复制链接** 复制付款链接(`eravon://open?e=…`)。**二维码** 以二维码显示链接;框左下 **保存图片** 把 PNG 存进你选的文件夹(那里已有同名的东西即不覆盖),**复制图片** 把图片放上剪贴板。
- **详细信息** 列出当前链接与旧版链接及其到期日。已发出的链接在到期前照常可下单。
- **在链上下架** 打开确认卡,写明这一版的商品与价格、**之后的付款** **开不了案,买家可取回**、**已开案** 的订单 **照常进行**。确认后发出下架交易(由卖家钥发,付 gas);之后页底只给 **发布新版本**,要再卖就改条款发布新版本。
- **删除草稿** 后点 **删除** 删除草稿,删除后不能恢复。

在以下情况下客户端会自动重新签名:有预签订单、链接临近到期、候选已更新、收款地址已更换(锁定期间以 **解锁后重新签名:** 列出原因)。

*商品页面与图片摘要的写法*:编辑页的两栏把它们写进商品说明正文的末尾,成一个围栏块,随正文一起算哈希、一起冻结;卖家商品页、买家付款页与卷宗里随案冻结的商品说明都按同一种写法读它,显示正文时不画这一块。直接在正文里写也是同一种写法:

````
```eravon.goods-refs/1
page https://shop.example/item
image <64 位小写十六进制的 SHA-256> 正面图.png
```
````

- 块须在正文的最末尾,且全文只有一个;
- `page <网址>` 至多一行,网址是一串不含空白的字符,照原样显示,能否打开由客户端的打开口判(只开 `http` 与 `https`);
- `image <SHA-256> <名>` 零到多行,摘要恰为 64 位小写十六进制,名是其后一个空格之后的整行(空格与中文照写),不得为空;
- 块内可有空行。块不合任何一条即当普通文字:正文照卖家所写显示,不带商品页面与图片,也不拒;说明里写什么都行(只贴一个哈希也可以)。

*分段交付*:一笔买卖分几段交付时,每段各是一件商品:第一段在 **基本信息** 的 **系列号** 里选 **新系列**(系列号由客户端生成),后面各段选已有的那个系列,再填各自的 **第几段** 与 **共几段**(选已有系列时自动填上段数与下一段);商品列表上每件写明它是系列的第几段、共几段。一个系列只许选一位候选,各段要同一位;后一段要等前一段写好并发布之后才写得成,它的开案窗与有效期由前一段推出(晚于前一段最晚可能结束的时刻),也不许买家自己开案。换钥之前把整个系列都发布上板:换钥之后才上板的后段,谁也付不进。

### 5.5 接收订单

**订单** 页有 **进行中** 与 **已完成** 两个分段、一行搜索(**订单号、买家或商品**、**开始日期**、**结束日期**),以及 **订单号**、**买家**、**商品名**、**截止**、**金额**、**状态** 几列。列表合并了本机记录的订单与链上找到的订单。卖家押金不够开案的订单,状态写「待部署 · 卖家押金不足」,以 **卖家押金不足** 标出并显琥珀色。

- **粘贴回执**(工具栏):粘贴买家复制给你的回执,点 **贴入**。客户端会对照你的商品记录核对回执,然后打开这笔订单。
- 点一笔订单打开详情。详情页有 **概况**、**交付物**、**争议**(出现争议后才显示)、**记录**、**费用** 几个页签。
- **概况** 顶上是一张概况卡:状态与截止,右端只放这一刻最常用的一个键(可交付时 **提交交付**,争议中 **上交证据**,已结束 **导出**,已到款待开案时 **立即开案**,其余不放键),下列 **金额**、**判官** 与 **下单**。其下是 **基本信息**:**商品名**、**状态**、**买家**(点进去为买家设一个仅本机的备注名,再点 **保存**)、**商品详情**(**随案冻结**,打开 **随案冻结的文书** 的 **条款** 页签)、**判官**(开案前写这一单选的候选,开案后打开 **本案判官**)。**状态** 一行只在开案前列出。再下是 **进度**(差额、提醒、在途交易与它的两个键,以及买家签名一格)与 **操作** 一组(其余的 **立即开案**、**导出**、**提交交付** 等;期限已过时另有 **到期结清**),然后是 **详细信息**(订单号、全精度金额、案号、合约、买家地址、判官地址、结算币合约)。链上读数说这一单可退款时,页底另有 **发起退款**。
- **随案冻结的文书** 全屏页有 **条款**(**条款要点** 与条款全文)、**商品说明**、**交付说明**、**摘要** 四个页签;**摘要** 列出各段摘要、**本案约法指纹**、**卖家要约签名**、**公告板上架交易**、**案号** 与 **合约**,逐行可复制,**导出全部文书** 打开导出页。本机没有的一项照写本机没有,不补假值。
- 订单页开着一单时按左下角 **同步**,另从链上读一轮这一单。买家的货款已足额到达订单地址、客户端已解锁且开着 **见款自动开案** 时,这一轮会发出开案交易,手续费由你的签名钥支付,判官费与押金从金库拉取;关着时不发,点 **立即开案** 才开。开案期限过了而案没开,买家可取回货款。
- **到期结清**(期限已过时才出现):按条款推进这一单。判官辞任后确认期过了,由你在这里放款。
- 按左下角 **同步** 时,除读链外另补扫:在链上查找你还没记录的订单(例如买家自己开的案),从开案交易补记,并补上已到账的付款。定时的同步只读,不发交易。
- 如果买家签了确认并把签名发给你,在 **进度** 一节把它粘贴到 **买家签名**,点 **核对并代为确认**。
- 订单状态随订单进程变化:待付款、待部署、待接单、待交付、待确认、已确认待对方提交、争议中、待抽签、已完成、已裁决、已和解、已退款、已结清、已过期、已撤单、已下架。
- *往代合约上的案*:合约换代之后,往代合约上的案默认不列;在设置 › 网络打开 **往代显示**(命令行与 AI 应用:`eravon <席>-settings-past-cases --on true`),它们就列在订单表里,标 **往代合约**,照它那一代的合约读写。那一代没有的动作(以调用同意的和解、撤单、过期退款、抽签、开案)键灰着,悬停写 **往代合约没有这一步**;往代合约的清单不能再付款开新案。开关关着时,对它的一切写动作都以 **往代合约上的案:在设置里打开往代显示后操作** 具名拒,一笔不发。

### 5.6 押金与交付

每单的判官费与押金在开案时从你的金库按授权额度拉取(见 5.12 节);订单页不再另存押金。**费用** 页签的 **押金** 一行显示这一单锁着的押金。

- **提交交付**(判官接单后可用):弹层里拖入文件或目录,或点左下 **选择文件或文件夹**,客户端计算文件清单并写明这一次清单含几个文件。实物交付可拖入发货凭证,或只写备注(快递与单号)。**备注(选填)** 随清单上链承诺,买家看不到,单号请另行告知;**送达方式(仅本机)** 只记在本机。然后点 **提交交付**。上链的只是文件清单;正文要另交给买家。交付后进入确认期;确认期过后,任一方可按 **到期结清** 放款。
- **交付物** 页签显示 **交付时间**、备注与文件(点文件可查看大小与 sha256),交易与所在区块在 **详细信息** 里。**另存本机原件** 一行的 **另存** 把交付的文件复制到「下载」目录下的一个文件夹;只有备注的交付没有这一行。
- 订单以放款或裁决结束且你分得一份时,**交付物** 页签列出在 ZIKARON Desk 登记授权所需的三个值:**被授权方**、**作品摘要** 与 **条款摘要**,各附 **复制**。

### 5.7 争议、证据、和解与退款

买家申请退款后出现 **争议** 页签。各键只在合约那一刻收这一手时出现;案结之后不再给。

该单有席位判官时,订单页的操作里有 **投诉判官**:写明投诉内容、附上手头的材料、选好文件夹,**生成投诉文件** 即以本席现行的钥签出一份 `eravon.complaint/1` 投诉档(格式见 `docs/complaint.md`)。去处从这一单本身读出:行会席位的案即成交所选的那家行会,具名判官即登记簿名录列了他的行会;单上列出行会名片,由你经名片上的联系方式把档发给行会,客户端不代发。判官不属任何行会时不出档。

- **申请** 显示 **发起** 时间、**裁决截止** 与 **买家已垫诉讼费**。买家的申请不选档位:判官在条款的全部档位里裁。
- **证据** 列出双方提交的证据。自己提交的可用 **打开原件** 打开。
- 争议页签的 **操作** 一组有 **上交证据**、**达成和解**,过了裁决期另有 **发起退款**。
- **上交证据**:在 **本机披露包** 中选一个(或 **不选**),并/或拖入文件或目录(左下 **选择文件或文件夹**);填写写给判官的 **说明(选填)**,点 **上交证据**。上链的只是证据清单的哈希;原件要另交给判官与对方。
- **达成和解** 分两步:
  1. **第 1/2 步 · 发出和解要约**:填写 **退给买家的比例(%)**(0 至 100,最多两位小数)和 **有效期(天)**(**1 天**、**3 天**、**7 天** 或 **自填**,1 至 7 天),点 **出要约**。要约以一笔交易发上公告板(以本案案号为键),手续费由签名钥付。比例为 100% 时改走全额退款。
  2. **第 2/2 步 · 等待买家签名**:卡上给出这份要约的链接(`eravon://open?e=…`)与 **复制链接**。买家在客户端里可直接按案号从公告板读出它,也可打开你发的链接。买家签名后,把签名粘贴到争议页签 **和解提议** 一行下方,点 **核对并和解**;买家也可以自己把和解提交上链。
- **发起退款**(在争议页签和概况底部)打开 **确认退款**,列出 **货款**、**判官费(从买家那一份扣)**、**退给买家**、**押金退回**,争议中另列 **其中诉讼费退还**。点 **确认退款** 发出退款。退款后订单结束,不可撤销。
- **条目** 显示判官的 **判词** 或 **辞任** 条目及全文。

#### 证据送达

原件按法交到判官手里,要加密给判官在自己账本里公布的收件钥;送达的渠道是当事人自己的,窗口不送,也不做中继。

- 卖家席概况的 **判官** 一行打开 **本案判官** 全屏页(概况 / 约法 / 报价):按地址现读在席判官最新的判官资料(抽签来的行会成员不在候选表上也能打开,并注由哪个行会抽中):名称、主页、**判官自述**、本案绑定的 **约法** 全文与开案时冻结的报价;还没有在席判官时照写。买家席订单详情的 **判官** 一行打开同一页。
- 争议页签的 **证据送达** 一卡示 **收件钥** 挑定与否。收件钥只按判官账本挑:挑不出唯一一把或判官没有公布时,写明原因,不导出,也不发明文。没读过时点 **读取判官与收件钥**。
- **上交证据** 成功之后(交付物页签的 **提交交付** 成功之后同),点 **导出密文包** 选一个文件夹:清单所列每个文件与清单本身各封成一份 `.age` 密文,文件名跟清单(披露包的 `zikaron-kit/` 路径照留)。原件在提交之后改过即拒,一个字节不写。一案在席判官多于一位时具名拒。
- 密文包经你自己的渠道交给判官;判官用自己的钥打开,逐项核对清单。买家席的订单页同样有这几处,走同一条路。

### 5.8 记录与费用

- **记录** 列出这笔订单在链上的每个事件及其时间;点一行查看交易哈希。
- **费用** 列出 **货款**、**判官费**(结束前为预估)、**押金** 与 **诉讼费**(已垫 / 应垫);订单结束后另列 **分账**,即买家、卖家、判官各得多少以及押金归买家的部分。

### 5.9 导出

**导出** 页(两个席位都有)有 **案件卷宗** 与 **对账单** 两个页签。

1. **挑选订单** 打开一张大弹层(上为关键词,下为开始与结束日期,每单一行);本机缺少文件的订单显示为灰色,右侧以 **本机缺** 标出缺什么。选好的订单列在 **所属订单** 一节,旁边的 **更换** 可另选。
2. **导出** 打开一张弹层:**保存到** 默认是上次导出的目录,弹层左下 **选择目录** 可改,确认即导出。

- **案件卷宗**:含条款、签名、交易与判词。写出之前,每一笔交易都与链上核对,卷宗格式也会自检;自检不过即拒绝导出。结果卡顶上写 **卷宗已导出,链上逐笔相符** 或 **卷宗已导出,下列几项不合或未重算**,附三种计数;其下列出 **条款与签名**、**交易记录**(几笔)、**终局**、**公告板上架交易**、**附件**(几份)、**判词**、**合规页**、**链上核对**(**不合** 或 **未重算** 的逐项一行)与 **自检**;写入的路径在结果卡的 **详细信息** 里。
- **对账单**:数据取自链上。结果列出 **终局**、**货款**、**判官费**(**从押金付**)、**押金**、**诉讼费** 与 **诉讼费出处**,再逐方列出 **买家所得**、**卖家所得**、**判官所得** 与 **卖家诉讼费归买家**(未结案时写 **结案后定**),以及 **交易记录** 笔数。条款中带合规块时,还会写出合规页,列明法定身份与折算,并注明来源与时刻。

已完成订单的 **导出** 按钮会打开本页并选中这笔订单。

### 5.10 首页与通知

- **首页** 显示四张卡片(**进行中** 及待处理项数、**本月收入**、在售 **商品**、可选的 **判官与行会**)、进行中的订单、可选的判官与行会,以及 **动态**(点一行查看交易哈希)。
- **通知** 只列要处理的事:交付到期、买家申请退款、需重新抽签、货款到账、卖家押金不足、价源陈旧、授权登记提醒、付款链接临近到期或需重新签名、备份落后(从没做过整机备份也算)。点一行即去处理它的地方(订单、商品或 设置 › 本机数据),**已处理** 把它从表上收起;一条也没有时写 **没有需要关注的事**。截止时间临近时,客户端按每个截止时间发一次系统通知。

### 5.11 公司模式

公司模式用于代公司操作:每一个原本要发交易的操作都改为导出提案,由公司执行。默认关闭;桌面设置页暂不列这一节,由命令行 `seller-settings-company`、`buyer-settings-company` 打开或关上,打开之后各页照下面各条走公司那一路。

- 打开时要给 `--company`(公司地址),先在多个节点上核对公司的合约,不能打开时说明哪一项不合。
- **时间核对**(默认开启,`seller-settings-time-check`、`buyer-settings-time-check`):开启时,截止期短于公司异议期的导出会被拒绝;关闭时,客户端询问 **仍要导出**。
- 公司模式下,商品版本不签名。商品页显示 **公司提案**:**导出提案** 为每位候选写一份登记提案到「下载」目录(登记后不可撤回),链接显示 **待公司通过**,直到 **核对登记** 读到全部登记。
- 订单中的交付、退款、证据与和解弹层都改为导出提案(**导出提案**),由公司执行。和解要约随这一份提案上公告板(同意的登记与上板同成或同不成),本席不另发。
- 不许买家自付 gas 开案的单,开案也由公司来:订单页给 **导出开案提案**,提案里是公司在已部署的实例上直接调的 init,原件附这一单的发布件与回执(实例还没部署时先由本席钥部署,谁都可以发;行会候选的单不经提案开案)。导出之后,页上列出提案路径与 **随附原件**。

### 5.12 卖家钱包

卖家席的 **钱包** 管押金的金库、收款与交易钥:

- **使用自带金库钱包**:默认开着,交易钥就是金库,押金放在这把钥上,不用登记。开着时卡下展开 **本机金库**:有余额的币一币一行;**转入** 给出地址与二维码;**转出** 选币种与金额,**转入地址** 与 **再填一遍转入地址** 都要填(第二格不收粘贴)。关上即回到外部金库,点 **设置金库** 填 **金库地址**。改了金库,在售商品要重新签名。
- **押金**:每单的判官费与押金从金库拉。押金卡写一句 **金库用来预扣押金**。按你已发布商品的每种结算币各一张卡:**已就绪**、**未登记** 或 **额度为零**,以及 **可用押金**(余额与给合约的额度取小)、**金库**、**余额**、**给合约的额度** 与 **登记**。每单开案时从金库拉判官费与保证金,结案时没付给判官或买家的部分退回金库,额度不随退回补;额度为这个金库登记过的所有卖家共用,收回登记即把额度调到 0。有待开案的订单时,卡上写够押几单(按每单自己的押金依次往下数;不够时写只够押几单、共几单待开案),并列出 **待开案订单各自的押金**;某单押金不小于货款、又开着允许买家自付 gas 开案时另有提示。标准换代后提示金库要对新合约重新授权、重新登记。
- **调整额度**:填给合约的额度(整数个币,格右写明单位),点 **调整额度**。本机金库由交易钥直接发出,手续费不够时写明还差多少。外部金库时客户端算出金库要发的几笔(先授权,再登记),每笔附二维码与 **用金库钱包打开**,由金库钱包签;发出后点 **发出后重读金库**,以链上读数为准。
- **收款**:货款打入的收款地址,**设置地址** 或 **更换**;不能是交易钥。
- **交易钥**:当前钥与它上面的 ETH。关着本机金库而钥上还有代币时,逐币列出并可 **转出**。换钥前先把代币转出。

## 6. 买家

### 6.1 在桌面客户端中付款

在买家席打开 **付款链接**,有 **付款** 与 **导入** 两个页签。点击、粘贴或扫到的付款链接会直接打开到 **付款**。

**付款**

1. 在 **粘贴付款链接** 下粘贴链接(`eravon://open?e=…`),点 **打开链接**。客户端从公告板读出链接所指的那一版。
2. **核验** 逐项显示 **通过** 或 **未通过** 及原因:**链接内容**、**条款**、**条款匹配**、**换钥簿**、**卖家自己登板**、**未撤下**、**判官资料**、**报价**、**标准**、**价格来源**、**卖家登记**、**要约钥现行**,读不到余额时另有 **余额**。**卖家自己登板** 不过,是这份清单不是卖家自己登的板,或是卖家钥交出记录之后才登的;**要约钥现行** 不过的候选隐去(条款许买家开案,而要约是卖家换下的旧钥签的、登记簿也没有)。卖家押金未到位的候选照样可选,行内写明付款后要等押金到位才开案。行会候选的名单太长、开案或抽签装不进一笔交易时,签单前具名拒(`E_ACT_GAS`)。
   **基本信息** 里点 **全部历史** 进入一页,看卖家这把钥所在记录在链上的全部历史(读的时候先是加载态,读不成写明原因):**已确认的钥**、**待认领**(已声明而未接任的那一把)、**文书**、**交出记录后的尝试**与 **当事方的案** 的条数。订单页的对方、付款页的每位候选也各有一行 **全部历史**。
3. **基本信息** 一节显示 **商品名**(条款只带商品说明的哈希时写 **私密商品**)、**金额**、**交付期限**(**判官接单后起算**)、**确认期限**、**付款来源**(你的当前钥)及其 **余额**、**卖家**(写短地址)。余额不足时页上横幅写明需要充值的地址与差额。
4. **商品描述** 一节列出 **商品说明** 与 **交付说明** 各一行,写明 **全文上板**、**已核对** 或 **未持有**;商品说明里写了商品页面时另有 **商品页面** 一行。点一行打开那一段的正文页:未持有的,把卖家另交的正文文件拖进来(或点 **选择文件**)核对哈希,相符的随订单存,不符即写明;已持有的商品说明可拖入图片核对摘要。缺段照样可签,签字卡上会写明这一单不带那一段的正文。
5. **退款档位** 逐档写 **退买家**、**卖家得** 与诉讼费由谁承担;其下是条款要点,**条款全文** 折在下面。
6. 在 **判官** 下点选一位候选:每行写裁决期、**判官费**、诉讼费(只在你申请退款时预付)与 **卖家押金**;不可选的一行变灰并写明原因。以参考币报价的候选行内标 **开案时定价**,候选之下写一次 **参考币报价:诉讼费与押金按价源换算,开案时定价**。选的是行会席位时,下方出现 **行会约法**:链上读到的报价与约法正文,写明 **签下这一席即接受此约法;正文与报价都从链上读出**。其下 **辞任条款** 一节逐位写出接单期与裁决期,点一行看这一位的辞任条款。
7. **退款地址** 默认为当前钥的地址;填入其他地址后点 **用这个地址** 生效。
分段交付的后段:照段序签,先签付前一段;前一段还没结束时,付款前页上就写明这一段付款后要等前一段以你零份额结束才开案,前一段退你份额或本段到期时款退回,付好之后再说一次。同一段已有一单时不另签一单,页上点出那一单,到订单页接着办它。

8. **付款** 打开确认卡片(商品名、金额、期限、所选判官、付款来源、判官费、诉讼费与卖家押金,行会席位另可展开约法)。在卡片上点 **付款**:先签署订单并存好回执与订单文件,再做开案前的核查;当前钥上有足够的结算币时从当前钥付款,条款允许买家开案时随即开案。结果显示 **已付款并开案**,或说明在哪一步停下(例如余额不足、卖家押金不足、价源陈旧或已下架)。余额不足时订单已签好,到 **订单** 里用别的钱包付款即可(见 6.2 节)。如果订单地址已被占用,客户端在下一秒重签;要约到期时间定死了这一单时拒签,请卖家另出一版。

**导入**

- **订单文件**:拖入或选择订单文件,点 **导入**。订单的买家钥须在本机;以调用同意的订单只读列出。
- 订单文件只由你递来:拖进 **拖入订单文件** 那一框,或点按那一框选择文件(对话框开在「下载」目录)。

公司模式下(见 5.11 节),**付款** 改为导出提案:选择 **登记式**(付款并登记,公司执行后由你开案)或 **直接式**(付款与开案在同一份提案中完成),点 **导出提案**,复制 **交卖家的回执**;提案的原件附带清单、条款与回执。登记式在公司执行后点 **开案提案**,导出开案那一份提案(部署与开案由公司直接调),公司执行即开案。

### 6.2 买家订单与售后操作

**订单** 有 **进行中** 与 **已完成** 两个分段、一行搜索(**订单号、卖家或商品**、**开始日期**、**结束日期**),以及 **卖家**、**商品**、**截止**、**金额**、**诉讼费缺口**、**状态** 几列。

打开订单可见 **概况**、**交付物**、**争议**、**记录**、**费用** 几个页签。**概况** 显示状态、截止、卖家、金额、判官、下单时间、钥,以及条款是否已保存(**条款已保存** 或 **条款未保存**)。往代合约上的案在买家席同样照往代案开关(见 5.5 节)。

案还没开时,概况顶上是一张随预算地址的读数而变的卡:

- **待付款**:**付款** 一节给出所欠金额的二维码(任一钱包扫码或 **用钱包打开**)、**复制地址**,以及等待到账的已到 / 应付。
- **待开案**:**开案** 一节写 **已到账** 的金额与等待开案的期限。条款允许买家开案时有 **我来开案**:部署与开案两笔从这里发出,开案即把押金与费用锁进本案。这一单已经开案时照实说,卡片关上;卖家押金不足时说 **卖家押金不足,这一单现在开不了案**:等卖家补足,或撤单退款。
- **逾期未开案**(开案期限过了)或 **已下架,可取回**(这一版已下架):**未开案退款** 一节写已到账的金额,点 **未开案退款** 把它退回退款地址,退成后说退了多少、退到哪与交易号。
- 前两种都有 **撤单** / **撤单退款**:开案前可撤单,已到账的原数退回。基本信息另列 **退款到** 与 **开案期限**(逾期全额退回)。
- 持有订单文件时,基本信息里有 **复制回执** 与 **回执二维码**(交给卖家,卖家凭它认出这一单),开案前后都在。

开案之后,可做的操作随状态而定:

- **到期结清**(期限已过时才出现,出现时放在概况卡右端):按条款推进或结清这一单,确认框列出买家、卖家与判官各得多少。待抽签的单照抽签区块给出。交付期限过了而卖家没交付,先点 **到期结清**,再 **取回** 退款。
- **确认收货**(待确认):显示 **付给卖家** 与 **判官费**;**确认放款** 把货款付给卖家,不可撤销。
- **交出确认**(待确认,钥在本机的订单):只签名,不发交易,不花 gas;签出的那一笔交给卖家或任何人提交。签出即同意放款:签出当时就记在订单上,状态写 **已确认,待对方提交**,此后不再给申请退款。
- **申请退款**(待确认,只在确认期内):不选档位。卡上写 **判官**、**应垫诉讼费**(现在预付)、**裁决范围**(条款的全部档位)、**逾期不裁**(判官到期不裁时落在哪一档,读开案时那份报价)与 **申请截止**(过期即放款给卖家);点 **预付并申请**,诉讼费从当前钥转入这一单,随即提出申请。判官在裁决期内裁决。
- **上交证据**(争议中):在弹层里选一个披露包,并/或拖入文件或文件夹、点左下 **选择文件或文件夹**,弹层里一行写明所选的名(没选写 **未选择**),然后点 **上交证据**。上链的只是清单的哈希;原件要另交。
- **同意和解**(争议中):点 **从公告板读取**,客户端按本案案号读出卖家发上板的最新一份要约;也可粘贴卖家发来的 `eravon://open?e=…` 链接,点 **读取要约**。页面显示 **退给买家的比例**、**有效至** 与 **卖家同意**(签名随要约,或已在合约登记)。点 **签名同意** 或 **以调用同意**。
- **取回**(订单结束后):填写币种地址(留空为结算币),点 **查询** 查看 **可取回** 的金额,再点 **取回**,取回后说取回多少、到哪与交易号。用于取回多付或误转的币。
- **导出**(已完成订单)打开导出页(见 5.9 节)。

**费用** 显示货款、判官费,结案后的 **买家所得**、**卖家所得**、**判官所得** 与 **卖家诉讼费归买家**,以及这笔订单自己发出的交易的手续费合计。

### 6.3 钱包

买家席的 **钱包** 使用当前钥:

- **余额** 概况卡写当前钥的名字,右端是 **收款** 与 **转出**;卡上列各种结算币与 ETH(用于手续费),**详细信息** 显示地址与精确的 ETH 数额。
- 换过钥之后,前任钥上收到的钱(换钥之前签的单退款、过期或和解时付到单上的收款地址)列在 **前任钥上的钱**,每把一行,点 **转到当前钥** 即转过来,每种币的手续费由当前钥付(ETH 留出它自己的手续费)。只剩不够它自己手续费的 ETH 零头不列。不开窗时同一手是 `buyer-wallet-former-move --former <前任钥> --token <币> --send true`。
- **收款** 打开一张弹层,显示地址、二维码与 **复制地址**。
- **转出**:选择 **币种**,填写 **金额** 与 **转入地址**,点 **转出**。**全部** 填入 **现在可转** 的数额(转 ETH 时 **已留出这一笔的手续费**)。
- **交易记录** 列出你的交易(时间、订单、类型、金额)。点一行查看状态(**已确认**、**已回滚** 或 **待确认**)、手续费、交易哈希与发出地址,并可 **复制哈希**。

### 6.4 买家首页与通知

**首页** 显示 **进行中**(及待处理项数)、**余额** 与 **已完成**,你的订单(其中 **待** 一列为 **你**、**卖家**、**判官** 或 **任何人**)以及动态。**通知** 只列要处理的事:待付款、待开案、待确认收货、可过期退款、有款可取回、收到和解要约,以及读不到待办的订单;点一行即去处理它的地方,一条也没有时写 **没有需要关注的事**。截止时间临近时,客户端按每个截止时间发一次系统通知。

## 7. 语言、外观与数据

- **语言**:设置 › 语言和时间 › **语言** 在中文与 English 之间切换,立即生效并保存。窗口启动时的语言由 `--lang` 决定(未给时为中文)。
- **时区**:设置 › 语言和时间 › **时区**:**UTC** 或 **跟随系统**(新装即是)。客户端显示的每个时刻(订单详情、首页动态、通知、上次备份、上次同步)都按所选的区写,订单表的日期筛选也按它切日;选项下面一行写出此刻的时刻。读不出本机时区时,时刻按 UTC 显示并在页上写明。签字的文档、答面与导出件照旧用 UTC。
- **外观**:设置 › **外观** › **主题**:**浅色**、**深色** 或 **跟随系统**。选择会保存,下次启动解锁后生效。
- *数据*:客户端保存的一切(金库、钥、身份、设置、商品记录、订单与操作日志)都在启动时给定的数据目录中(设置 › **本机数据** 写出它在哪)。把整个用户目录拷到别的盘或别的用户名下,客户端读写的是拷过去的那一份,不碰原处,头一回打开时说一次数据从哪里搬来。另存的原件与公司提案默认写入「下载」目录,二维码图片存进你选的文件夹;密钥文件与整机备份写入弹层里所选的 **保存位置**。

## 8. 命令行

`eravon` 程序在终端中提供与卖家、买家相同的操作,每个都是带席位名的平铺动词:`eravon seller-<命令> [--参数 值 ...]` 与 `eravon buyer-<命令> [--参数 值 ...]`,`eravon contract` 列出全部动词。桌面能改的,除了只有窗口才需要的四样(自动锁定、刷新周期、语言、外观),都有对应的动词。每个动词只输出一个 JSON 答复,拒绝也是答复;退出码 0 表示成,1 表示拒,2 表示用法错(此时没有 JSON),3 表示连发停在中途(已发出的逐笔列在 `txs`),4 表示链、网络或磁盘没能答复,一笔交易已发出而等到时限还没上块也是 4(`E_TX_NOT_YET`,带交易号 `tx` 与已等秒数 `count`;再跑同一条命令即先按交易号问它)。给 `--desktop <数据目录>` 时,由持着那个目录的桌面程序来做(设置 › 命令行与 AI 控制 › **经桌面 App 操作** 须开着):相对路径先化成全路径再交过去,经桌面的拒照同一个名直跑的退出码退;数据目录由另一台机器在写时不走桌面,答与直跑同(`E_STORE_OTHER_MACHINE`)。往代合约上的案,往代案开关关着时命令行对它的写动词同样具名拒(`E_A1_PAST_CONTRACT`)。完整说明见 `CLI-SCHEMA.md`。

本窗解锁且持着这一数据目录时,命令行凡写数据目录或发送(`--send true`)的动词由本窗以它已解锁的钥做完,命令行不必给口令。要签字或要发送的请求(要约、和解、交付、退款、确认、维权与结算,以及带 `--send true` 的每一笔)到了本窗先弹 **命令行请你签字**(只读、只扫或只出调用数据的请求不弹,即刻做完):列出 **动作** 与 **带来的参数**,写明 **不认识这一请求就拒绝:代理只跑腿,签不签由你定**;点 **同意并签** 才签并发出,点 **拒绝这一请求** 即什么也不签,命令行收到拒答。**待上链** 页列出终局未知的直发(**核查**、**作废**:只在它再也上不了链时才收)与有交易在途的订单(点开即到那一单)。改口令、动金库的动词总是在本窗里做。

*代理须知*:替人跑腿的程序(包括 AI 代理)认出 `eravon://open?e=` 链接或 `eravon.link/1` 载荷,就把它交给本机的客户端(`eravon-app window --url <链接>`,或经 `--desktop` 的命令行动词),由客户端核验并由用户在桌面上点头。代理永远不持钱包与钥。
