# Wiring audit

This document lists every user-facing surface of ERAVON and answers three questions for each one:

1. **Real work.** Does the interaction do real work? The cell names the function that performs the action: it writes to disk, sends a transaction, or calls a library that does.
2. **Real source.** Does the display have a real source? The cell names the function that reads what is shown: disk state, chain reads, or a library computation.
3. **Precondition.** Is the precondition chain built inside the product? The cell names the product functions that establish what the surface needs (a vault created and unlocked, an endpoint table, an identity directory, an issued payment link), so that no hand-built environment is required.

A surface is a page, a coherent control group on a page, or a command-line verb group. The **Note** column records findings plainly: a handler that only changes display state, a display without a real source, or a precondition that the product does not establish by itself.

Code references are written as `path symbol` in backticks: the path is relative to the repository root, and the symbol (a function, method, constant or type) is defined in that file. A test in the project checks that every reference resolves: the file exists and defines the symbol. A cell holds at most three references, separated by "; ". Moving a definition within its file needs no change here; renaming it or moving it to another file re-points its references in the same commit.

The desktop app reaches every library through the same page objects in both the window and its scripted driver, so one reference covers both routes.

## Command line

Verbs run as `eravon seller-<verb>` and `eravon buyer-<verb>`. Routing goes through `crates/eravon-cli/src/verbs.rs run` to `crates/eravon-cli/src/seller.rs run` and `crates/eravon-cli/src/buyer.rs run`. Chain verbs take endpoints from `--endpoint`, then `--table`, then the identity settings, in `crates/eravon-cli/src/home.rs table`. A verb sends a transaction only with `--send true` and `--passcode`.
